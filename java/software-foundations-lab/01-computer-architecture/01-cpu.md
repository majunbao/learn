# 01 — CPU Structure

> Syllabus reference: P2–P19
>
> The **Central Processing Unit (CPU)** is the brain of the computer.
> Understanding its internal structure — ALU, CU, registers, and the
> instruction cycle — is the foundation for everything else in this
> module: addressing modes, pipeline, interrupt handling, and more.

---

## 1. CPU Overview

```
┌──────────────────────────────────────────────────────┐
│                        CPU                            │
│  ┌─────────────┐  ┌──────────────┐  ┌─────────────┐ │
│  │     ALU      │  │  Registers   │  │   CU        │ │
│  │ (Arithmetic  │  │  (General +  │  │ (Control    │ │
│  │  Logic Unit) │  │   Special)   │  │  Unit)      │ │
│  └──────┬───────┘  └──────┬───────┘  └──────┬──────┘ │
│         │                 │                  │        │
│         └────────┬────────┘──────────────────┘        │
│                  │                                    │
│            Internal Bus                               │
└──────────────────────────────────────────────────────┘
                   │
              System Bus
           (to memory / I/O)
```

The CPU consists of three major components:

| Component | Chinese | Function |
|-----------|---------|----------|
| **ALU** | 算术逻辑单元 | Performs arithmetic (add, sub, mul, div) and logic (AND, OR, NOT, XOR) operations |
| **CU** | 控制单元 | Generates control signals to coordinate all parts; decodes and executes instructions |
| **Registers** | 寄存器组 | Fastest storage inside CPU; holds operands, results, addresses, status |

---

## 2. ALU — Arithmetic Logic Unit

The ALU is the **computation engine**. It receives data from registers,
performs the requested operation, and outputs the result plus status
flags.

### 2.1 ALU operations

| Category | Operations |
|----------|-----------|
| Arithmetic | ADD, SUB, MUL, DIV, INC, DEC |
| Logic | AND, OR, NOT, XOR, shift, rotate |
| Compare | CMP (sets flags without storing result) |

### 2.2 Status flags (condition codes / 状态标志)

After each ALU operation, the following flags are set:

| Flag | Name | Meaning |
|------|------|---------|
| **ZF** | Zero Flag | Result is zero |
| **CF** | Carry Flag | Unsigned overflow (carry out of MSB) |
| **SF** | Sign Flag | Result is negative (MSB = 1) |
| **OF** | Overflow Flag | Signed overflow (result exceeds representable range) |
| **PF** | Parity Flag | Low byte has even number of 1-bits |

> Exam tip: CF vs OF is a classic trap. **CF** = unsigned overflow,
> **OF** = signed overflow. They are independent; both can be 1 at the
> same time.

### 2.3 Overflow detection (8-bit example)

```
  0111 1111  (+127)
+ 0000 0001  (+1)
= 1000 0000  (−128 in two's complement)  → OF = 1, CF = 0
```

```
  1111 1111  (255 unsigned)
+ 0000 0001  (+1)
= 1 0000 0000  (256, needs 9 bits)  → CF = 1, OF = 0
```

## 3. CU — Control Unit

The CU is the **conductor**. It fetches instructions from memory,
decodes them, and generates the control signals that drive the ALU,
registers, and buses.

### 3.1 Two implementation approaches

| Approach | Chinese | How it works | Pros | Cons |
|----------|---------|-------------|------|------|
| **Hardwired** | 硬布线控制器 | Control signals generated by combinational logic circuits | Fast | Inflexible; hard to modify |
| **Microprogrammed** | 微程序控制器 | Control signals stored in a **control memory (CM)** as microinstructions | Flexible; easy to extend | Slower (extra memory access) |

> Exam tip: "Which CU is faster?" → Hardwired. "Which is easier to
> modify / extend?" → Microprogrammed.

### 3.2 Microprogrammed control — key terms

| Term | Chinese | Meaning |
|------|---------|---------|
| Microinstruction | 微指令 | One step of control signals; stored in control memory |
| Microprogram | 微程序 | Sequence of microinstructions for one machine instruction |
| Control memory (CM) | 控制存储器 | ROM that holds all microprograms |
| Microinstruction format | 微指令格式 | Horizontal (one bit per signal) vs vertical (encoded fields) |

**Horizontal vs vertical microinstruction format:**

| Feature | Horizontal | Vertical |
|---------|-----------|----------|
| Bits per microinstruction | Many (one per control signal) | Few (encoded fields) |
| Parallelism | High (multiple signals at once) | Low (one field decoded at a time) |
| Speed | Fast (no decoding) | Slower (needs decoder) |
| CM size | Large | Small |

## 4. Registers

### 4.1 Classification

| Type | Chinese | Examples | Purpose |
|------|---------|----------|---------|
| **General-purpose** | 通用寄存器 | R0–Rn, AX/BX/CX/DX | Hold data and addresses; programmer-visible |
| **Special-purpose** | 专用寄存器 | See below | Dedicated roles; some programmer-invisible |

### 4.2 Key special-purpose registers — memorise these

| Register | Chinese | Role |
|----------|---------|------|
| **PC** (Program Counter) | 程序计数器 | Holds the address of the **next** instruction to fetch |
| **IR** (Instruction Register) | 指令寄存器 | Holds the **current** instruction being executed |
| **MAR** (Memory Address Register) | 地址寄存器 | Holds the address to read from / write to memory |
| **MDR** (Memory Data Register) | 数据寄存器 | Holds data being transferred to / from memory |
| **PSW** (Program Status Word) | 程序状态字 | Holds condition flags (ZF, CF, SF, OF) + CPU mode |
| **SP** (Stack Pointer) | 堆栈指针 | Points to the top of the stack |

> Exam trap: **PC** holds the *next* instruction address, not the
> current one. **IR** holds the *current* instruction, not the next.

## 5. Instruction Cycle

Every instruction goes through a series of steps. The basic cycle:

```
┌──────────┐    ┌──────────┐    ┌──────────┐
│  Fetch   │───►│  Decode  │───►│ Execute  │
│  取指    │    │  分析    │    │  执行    │
└──────────┘    └──────────┘    └──────────┘
```

### 5.1 Fetch sub-cycle (step by step)

```
1. PC → MAR          (put instruction address on address bus)
2. MAR → Memory      (address sent to memory)
3. Memory → MDR      (instruction word returned)
4. MDR → IR          (instruction placed in IR)
5. PC ← PC + 1       (advance to next instruction)
```

### 5.2 Decode sub-cycle

CU decodes the opcode in IR → determines which operation to perform
and which operands are needed.

### 5.3 Execute sub-cycle

ALU performs the operation; result written to register or memory.

### 5.4 Interrupt cycle (if applicable)

If an interrupt is pending and interrupts are enabled:

```
1. Save PC (and PSW) to stack
2. Load PC with interrupt handler address
3. Continue fetch-decode-execute from handler
```

### 5.5 Complete instruction cycle

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  Fetch   │───►│  Decode  │───►│ Execute  │───►│ Interrupt│
│          │    │          │    │          │    │ (if any) │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
     ▲                                               │
     └───────────────────────────────────────────────┘
```

## 6. Instruction Format

A machine instruction typically contains:

```
┌──────────────────┬──────────────────────────────────┐
│   Opcode         │   Operand(s)                     │
│   操作码         │   操作数                         │
└──────────────────┴──────────────────────────────────┘
```

| Field | Purpose |
|-------|---------|
| **Opcode** | Specifies the operation (ADD, MOV, JMP, etc.) |
| **Operand** | Specifies the data or address; can be 0, 1, 2, or 3 operands |

### Opcode encoding strategies

| Strategy | Description | Trade-off |
|----------|-------------|-----------|
| **Fixed-length opcode** | All opcodes same bit width | Simple decode; wastes bits for small instruction sets |
| **Variable-length opcode** (Huffman / prefix) | Common ops get short codes | Compact; complex decode hardware |
| **Expand opcode** (扩展操作码) | Opcode length varies with address count | Flexible; used in many real ISAs |

### Expand opcode example (16-bit instruction, 4-bit address field)

| Address count | Opcode bits | Address bits | Max opcodes |
|---------------|-------------|-------------|-------------|
| 3 addresses | 4 | 4+4+4=12 | 15 (0000–1110) |
| 2 addresses | 8 | 4+4=8 | 15 × 16 = 240 (1111 xxxx) |
| 1 address | 12 | 4 | 15 × 16 × 16 = 3840 |
| 0 addresses | 16 | 0 | remaining |

> Exam tip: "Expand opcode" questions ask you to calculate the maximum
> number of instructions given a fixed instruction word length and
> address field width.

## 7. Worked Example

**Q.** A CPU has a 16-bit instruction word. Each address field is 4
bits. Design an expand opcode scheme that supports:
- 15 three-address instructions
- 12 two-address instructions
- 62 one-address instructions
- as many zero-address instructions as possible

**Solution:**

| Type | Opcode pattern | Count |
|------|---------------|-------|
| 3-address | `0000–1110` (4 bits) + 3×4-bit addresses | 15 |
| 2-address | `1111 0000–1111 1011` (8 bits) + 2×4-bit addresses | 12 |
| 1-address | `1111 1100 0000–1111 1111 1101` (12 bits) + 1×4-bit address | 62 |
| 0-address | `1111 1111 1110 xxxx–1111 1111 1111 xxxx` → 2 patterns × 16 = 32 | 32 |

Wait — let's recount. After 62 one-address instructions, we used
`1111 1100 0000` through `1111 1111 1101` (12-bit opcodes). The
remaining 12-bit prefixes are `1111 1111 1110` and `1111 1111 1111`,
each with 4 free bits → 2 × 16 = **32 zero-address instructions**.

## 8. Exam-Style Questions

**Q1.** Which register holds the address of the **next** instruction?
A. IR  B. MAR  C. PC  D. MDR
> Answer: C (PC).

**Q2.** After the ALU adds two signed 8-bit numbers and the result is
`1000 0000`, which flags are set?
A. ZF=1, OF=0  B. SF=1, OF=1  C. SF=1, OF=0  D. CF=1, OF=1
> Answer: B (SF=1 because MSB=1; OF=1 because positive + positive gave
> a negative result in two's complement).

**Q3.** A microprogrammed control unit is ___ than a hardwired one.
A. faster  B. slower  C. the same speed  D. depends on clock
> Answer: B (slower, because it must read microinstructions from
> control memory).

**Q4.** During the fetch cycle, the sequence of register transfers is:
A. PC→IR→MAR→MDR  B. PC→MAR→MDR→IR  C. IR→MAR→MDR→PC  D. MAR→PC→MDR→IR
> Answer: B.

**Q5.** In an expand opcode scheme, if the instruction word is 20 bits
and each address field is 6 bits, what is the maximum number of
two-address instructions if there are exactly 8 zero-address
instructions?
> 20 bits total. Zero-address: 20-bit opcode, 8 instructions → uses
> 3 bits of the top, leaving 2^17 − 8 patterns.
> Two-address: 20 − 12 = 8-bit opcode. But we must reserve some
> patterns for zero-address and one-address. This is a design question;
> the key insight is that expand opcode trades opcode space between
> instruction formats.

**Q6.** Which of the following is NOT a special-purpose register?
A. PC  B. IR  C. R0  D. PSW
> Answer: C (R0 is a general-purpose register).
